HHireFlow AISYSTEM ARCHITECTURE

AI assistance · request lifecycle

One guarded path from hiring screen to AI insight.

HireFlow keeps live model access behind a single server function. The browser sends task-specific hiring context; the server authenticates the caller, applies task instructions, and returns advisory text for a person to review.

AI can summarize and draft. Hiring decisions stay with people.

Task modes

Selected by the calling screen, not inferred by the model.

5 MODES
candidate

Screening brief: strengths, risks, targeted interview questions, and a recommendation label. Context includes candidate, requirement, and deterministic scores.

contract

Compliance review of contract text against the requirement, with clause severity and suggested fixes.

feedback

Interview feedback summary covering overall impression, strengths, concerns, and a suggested next step.

jd

Inclusive job description draft with role, responsibilities, must-have skills, and nice-to-have sections.

ask

Concise, practical answers based on the hiring data supplied by the AI control center.

Runtime behavior

What the implementation does around the model call.

Prompt and output

  • Each task has its own system instruction; all share a rule that a human makes final hiring, rejection, compensation, and offer decisions.
  • Requests ask for short, plain text with simple dash bullets. The server awaits the completed text before returning it.
  • Provider options request low reasoning effort and set store: false.
  • The component keeps the result in local UI state and optionally notifies its onResult callback.
  • HTTP 429 and 402 receive specific messages; other model failures return a generic retry message.
Authorization detail to verify

The project note describes AI as staff-only, but this handler currently only denies a positive CANDIDATE role result; it does not require a positive staff role. It also does not explicitly stop if the has_role RPC returns an error. The AI key remains server-side, but the role gate should be confirmed against the intended access policy.
